# P0.1 Agent Execution Lite 决策记录

状态：Resolved（2026-07-21）

以下决策已由项目负责人确认，作为 P1 及后续阶段的实现依据。

## E1 claude 环境模式

- A：正式与本地运行都强制 `--bare`，要求显式 Anthropic 凭据。
- B：始终使用当前 claude CLI 登录与本机配置，不支持 `--bare`。
- C（推荐）：同时支持；本地默认使用当前 CLI 会话，标记为非完全受控；正式可复现 Run 显式使用 `--bare`。

决议：E1-C。

## E2 默认工具权限

- A（推荐）：默认只允许读取、列举和搜索 Case 工作区；编辑、Shell、网络和外部目录都需 Profile 显式开启。
- B：默认允许 Agent 自身的标准工具集，只禁止外部目录。

A 更适合结果分析 Benchmark，也能避免 Case 内容触发不必要的副作用。

决议：E2-A。

## E3 Candidate Report 提取

- A（推荐）：取最后一个成功 Assistant 最终文本；原始 JSON 事件单独保存，不要求 Agent 写报告文件。
- B：强制 Agent 在工作区写入固定文件，再读取文件作为报告。

A 对两个 Agent 的接口更一致，也避免把文件写入能力混入报告质量。

决议：E3-A。

## E4 隔离等级

- A（推荐）：MVP 使用独立临时工作区 + Agent 工具权限限制，并明确只支持受信任 Agent/Case。
- B：首版即要求每个 Agent Run 在容器内执行。

A 能先交付 Windows 本地版本；它不是针对恶意代码的安全边界。B 更安全但会扩大跨平台、镜像和凭据挂载范围。

决议：E4-A。

## E5 自动重试

- A（推荐）：只自动重试 Worker 中断和明确的临时启动错误；超时、认证失败、非零退出和无最终报告不自动重试。
- B：所有失败自动重试一次。

A 避免将随机重跑后的成功结果伪装成一次稳定执行。

决议：E5-A。

## E6 CLI 管理方式

- A（推荐）：用户预先安装并登录 claude/OpenCode；AnalystBench 只检测版本和调用，不负责安装升级或管理凭据。
- B：AnalystBench 自动下载安装并维护两个 CLI。

决议：E6-A。

## E7 默认执行限制

- A（推荐）：单 Case 30 分钟、原始输出 10 MiB、每种 Runner 默认并发 1；Profile 可调，Manifest 记录实际值。
- B：不设统一默认值，创建 Profile 时全部必填。

决议：E7-A。
